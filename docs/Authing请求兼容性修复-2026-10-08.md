# Authing 请求兼容性修复

日期：2026-10-08。状态：本地修复，未推送/部署；真实个人认证尚未通过。

## 依据

用户提供的附件包含回调日志：stage=token、category=AUTH_OPERATION_FAILED，耗时 61 毫秒，CPU 5 毫秒。只读取并提取必要诊断字段；原始请求头、Cookie、授权码、IP 等不复制到本记录或公开提交。

日志确认失败发生在凭证交换阶段，未进入签名校验和账户保存；不是 10 秒超时，也没有 CPU 超限结果。异常原文未记录，日志本身不能单独确定具体异常。

代码核对发现 token 和用户信息请求使用 redirect:error。Cloudflare workerd 官方源码明确只接受 follow/manual，error 参数会直接引发 TypeError。该代码缺陷确定存在，与日志中的快速失败吻合；先修正后仍需真实回调复验，不能据此保证没有后续认证配置问题。

来源：https://github.com/cloudflare/workerd/blob/main/src/workerd/api/http.c%2B%2B （2026-10-08 查看 Request 构造及 tryParseRedirect）。文档和运行时实现存在不一致，本轮以实际实现约束为依据。

## 修改与安全边界

- 将两处请求改为 redirect:manual。响应非 2xx 时直接拒绝，不自动跟随重定向，不转发 Authorization、密钥或令牌到其他地址。
- 原 state、浏览器绑定、PKCE、nonce、签名、邮箱验证与账户隔离保持不变；未改 D1 表、生产变量或用户数据。
- 已检查 jose JWKS 请求使用 manual，无需修改依赖。
- 修复使用项目理解守护规则保持仅账户排查范围，不把本地测试当成线上有效认证。

## 验证范围

账户专项测试模拟 workerd 拒绝 error 参数，覆盖有效合成身份、用户信息请求、token 和用户信息重定向被拒绝、不创建账户/会话，以及原认证保护。不是实际 workerd 执行，也不是用户真实 Authing 登录。

原测试在 Node 中验证，未覆盖这项 Cloudflare 运行时限制，这是此前验证不足。后续交付需区分本地模拟、目标运行时测试和真实生产登录。
