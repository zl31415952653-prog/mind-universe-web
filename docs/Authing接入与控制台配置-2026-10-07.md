# Authing 接入与控制台配置

日期：2026-10-07。状态：本地实现，未部署，未完成真实登录和云快照验收。

## 边界与流程

用户主动点击登录 → 本站建立 10 分钟一次性校验 → Authing 托管页面注册/验证邮箱/登录 → 本站回调交换授权码并核验身份令牌 → 建立本站会话 → 用户主动保存或恢复快照。

密码只交给 Authing；本机笔记不随登录上传。本站只记录服务商身份标识和已验证邮箱。Authing 的准确存储区域、免费版有效期及实际邮件送达仍待控制台/服务条款核对。第三方登录本轮未启用。

## Authing 控制台

以下是本轮新增接口的配置目标；先保存配置，部署之前网站还不能接收真实回调。

| 字段 | 目标值 |
| --- | --- |
| 登录回调 URL | `https://mind-universe-web.pages.dev/api/auth/callback` |
| 发起登录 URL | `https://mind-universe-web.pages.dev/api/auth/start` |
| 登出回调 URL | 本轮留空，退出本站会话，不发起 Authing 全局登出 |
| 授权模式 | `authorization_code` |
| 返回类型 | `code` |
| 换取 token 身份验证方式 | `client_secret_basic` |
| ID Token 签名算法 | `RS256` |
| Scope | 允许 `openid email`；不请求 `offline_access` |

认证地址保持现有值，不刷新 App Secret。注册使用邮箱密码，要求验证邮箱；关闭本轮不使用的手机短信/第三方入口。核对应用是否向所有已注册用户开放、发出的身份信息包含 `email` 与布尔值 `email_verified`。若页面字段不同，先截图（隐藏密钥）核对，不盲改。

## 旧账户与会话

旧用户及快照不改动；新身份按 issuer+subject 映射，不按邮箱认领已有账户。邮箱冲突时停止登录并提示需要迁移，不能用别的邮箱绕过后假称恢复了旧快照。迁移需先核查旧账户所有权与备份，由用户确认后另行处理。

Authing 模式不接受旧密码接口/旧令牌。新会话使用高熵随机令牌（服务端存 SHA-256 摘要），HTTP-only、Secure、SameSite=Lax，30 天固定有效期；无滚动续期、无自动云同步。退出本站会删除本站会话，Authing 上游会话不自动清除；登录请求使用 `prompt=login`。

## 验收顺序

1. 备份本地数据，不更换域名、不清除浏览器存储。
2. 用新测试账户走真实邮箱验证/登录，拒绝旧账户冲突和未经验证邮箱。
3. 回调进入本站后 `/api/auth/me` 确认有 user；配置入口 ready 只表示配置齐全，不证明表或服务可用。
4. 保存一份合成测试快照，退出，再登录并恢复；恢复会覆盖本机，先导出。
5. 校验第二个账户不能读取第一账户快照；验证过期、错误 state、重复回调均失败。
6. 实测 Workers Free CPU 与 D1 操作；本轮不对 10ms 预算作未实测的保证。
7. 正式推广前仍需生产限流、防滥用、邮件额度监控、数据区域/隐私审核和旧账户迁移方案。

参考：Authing 官方 OIDC 授权码文档 https://docs.authing.cn/v2/guides/federation/oidc.html 。本轮采用服务端授权码交换，附加 PKCE、state、nonce 和 RS256 签名核验；密钥不进浏览器。官方说明不是本项目实际验收结果。
