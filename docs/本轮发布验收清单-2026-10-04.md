## 2. 提交范围与排除项

现有工作区含多轮未提交改动，不能直接 `git add .` 或全部提交。先逐项确认本次变更来源和依赖。

- 必须成套核对：`src/` 的学习界面/解析/参考/PDF 模块与共享提示词 `src/learningPrompt.ts`，以及 `functions/api/learning/analyse.js`、`functions/_lib/learningModelOptions.*`、`learningReferences.js`。漏掉未跟踪的新依赖会导致远端构建失败。
- 账户相关 `functions/api/auth/` 和 UI 改动需一起核对；没有增加新的数据库迁移文件，本次仍依赖原有两份迁移，不能推断生产已执行。
- 测试代码、公开原创摘要与来源说明可纳入；`AGENTS.md` 和其他文档需检查是否包含仅本机信息后再决定，不因未跟踪而自动公开。
- 禁止提交：`下载资源清单/` 全文、`tmp/` 的论文页截图、真实凭证、个人备份、浏览器数据、截图中的个人材料。`tmp/` 当前不在忽略规则中，必须明确排除。
- 本轮只读检查：Git 已跟踪列表中未发现论文 PDF 或上述资源目录；仅发现 `.dev.vars.example` 模板。这不是完整凭证扫描，也不证明所有文档或 Git 历史安全。

## 3. 发布步骤（需明确批准后执行）

1. 审阅选定文件差异和新增文件；检查凭证及论文全文/截图排除情况。
2. 运行全部测试与构建，记录最终提交编号。
3. 用户批准后一次提交并推送 GitHub，触发一次 Cloudflare 构建；不循环小改动重建。
4. Cloudflare 构建成功后核对生产提交编号和主域名；失败则读取构建日志，不把绿勾等同于功能完成。
5. 生产 D1：核对绑定名称 `DB`、两份迁移及函数日志。使用独立测试账户，不使用已公开密码。
6. 生产操作：新建学习项目 → 合成文字导入 → 三种任务分支 → 刷新；分别验证桌面和手机。测试资料不冒充论文。
7. 手动云快照：先导出备份，只在独立测试数据环境验证保存与恢复，不能覆盖用户当前数据。
8. 托管 AI：配置未公开的新服务端密钥，先使用合成短材料；论文正文外发需单独获得授权。

## 4. 未通过处理

- 构建失败：停止上线验收，定位依赖/类型/配置问题。
- D1 或登录失败：保留本地使用，不宣称云同步可用；查看函数错误与生产绑定/表结构。
- AI 响应不完整：显示失败，不确认候选、不创建任务；核对额度返还。
- 恢复异常：停止覆盖数据，用导出备份恢复；没有备份不能继续试覆盖。
- 移动端或持久化异常：记录复现条件并修复，不以桌面测试代替全面验收。
