## 观察与未知

- 线上只读请求 `/api/auth/me` 返回 401 与 `user:null`。仅证明未登录请求能到达账户路由；无 Cookie 时代码不查询 D1，所以这不证明数据库已绑定或迁移成功。
- 仓库 `functions/_lib/auth.js` 使用 PBKDF2-SHA256 210000 次，同时用于密码和会话令牌。Cloudflare workerd 的 100000 次限制存在官方仓库记录；提高上限的 PR 在本次查阅时仍为 Open。这是重要兼容性疑点，尚无本项目生产日志确认。
- 不能把截图里的通用服务错误一律认定为缺表。D1 缺绑定、缺表、哈希异常及其他服务异常需分开。
- 本机没有填好数据库 ID 的 wrangler 配置，本轮没有可读取生产 D1 表和函数日志的已验证连接。

官方来源：https://github.com/cloudflare/workerd/issues/1346 与 https://github.com/cloudflare/workerd/pull/7550 （2026-10-04 查阅）。

## 本轮修改

新增固定故障分类：加密运行时限制 `AUTH_CRYPTO_UNSUPPORTED`、数据库缺表/缺列 `AUTH_SCHEMA_UNAVAILABLE`、其他 `AUTH_SERVICE_UNAVAILABLE`。注册、登录和会话查询使用固定安全文案，不向浏览器返回原始异常、SQL、令牌或账户细节。此修改用于诊断，不是根因修复。

没有降低哈希次数，没有修改既有密码格式，也没有删除账号。调整密码算法前需要考虑运行时可用性、安全强度、旧账户兼容和会话处理，不能直接把 210000 改成 100000 并宣布修复。

## 收到生产日志后的本地兼容修复

用户提供的注册日志明确记录 `NotSupportedError`：请求 210000 次，运行时拒绝超过 100000 次；响应为 503。事件 outcome 为 ok 不等于业务成功。只摘录错误类别，不复制日志中的 IP、地理或 TLS 信息。

新增 `passwordHash.js`：原生路径遇到明确迭代次数限制时，使用固定版本依赖 @noble/hashes 2.0.1 的同算法兼容实现。仍是 PBKDF2-SHA256、210000 次、32 字节、UTF-8、十六进制；没有降低次数，没有改数据库或密码，没有删除账号。其他异常不触发回退。与 Node 原生结果比对，包括 Unicode 密码和 session 盐，29 项测试通过。

**发布阻塞：** 兼容路径耗时明显高于原生路径。该实现解决算法输出兼容，不保证 Cloudflare 免费层 CPU 预算足够，不能把 Node 测试通过写成线上可用。需要实际 Workers 运行时 CPU 验收和计划额度确认；若超预算，应另行确定兼容的托管认证或运行方案，不能静默开通付费服务、降低保护强度或继续部署猜测。当前未部署。
